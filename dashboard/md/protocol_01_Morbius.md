# Протокол тестирования: Mórbius

**Дата тестирования:** 07.07.2026
**URL:** https://mdcopilot.online/morbius
**Категория:** FOR ALL

## Описание сервиса (по данным "Learn more about the service")

Mо́rbius — продвинутый медицинский AI-агент, сочетающий генеративный ИИ с верифицированными медицинскими базами данных.

Режимы работы:
- **Basic chat** — Q&A формат с сохранением контекста диалога.
- **PRO mode** — для сложных логических вопросов и задач, использует более мощные (и дорогие) модели.
- **Web search** — быстрый доступ к актуальным данным, статьям и новостям.

База знаний: клинические рекомендации (NCCN, ESMO, ASCO, RUSSCO), материалы конференций ASH-2025/EHA-2026/ASCO-2026, медицинские калькуляторы, PubMed/PMC/OpenAlex/MedRxiv/BioRxiv/FDA.

Дополнительно: загрузка файлов (PDF/Word/изображения) с анализом контента, генерация справок/направлений/бланков, экспорт ответа в Word, выбор "скиллов" (например, "Лабораторная диагностика", "Researcher" — с автоматическим сохранением обзора литературы в Word).

**Тарификация:** обычный запрос — 1 кредит, web search +1, анализ изображения +3. PRO-режим ("Expert"/"Professor") — 3 и 8 кредитов за первичный запрос, каждый доп. цикл рассуждений — 2 и 6 кредитов соответственно. При нехватке кредитов баланс может уйти в минус.

## Тестовый запрос (Standard mode, без ручного включения web-search/PRO)

**Промпт (на русском):**
> Пациентка 62 лет: ХСНсФВ (ФВ 55%), ХБП 3б (СКФ 38), СД2 на инсулине, стабильная стенокардия. Подбери схему терапии с учетом актуальных рекомендаций ESC/ACC, обоснуй выбор препаратов, укажи противопоказания и лекарственные взаимодействия.

## Наблюдаемое поведение системы

1. Даже в базовом режиме система автоматически инициировала цепочку инструментов: поиск по клиническим рекомендациям, несколько раундов web-search (видны статусы "Searching: ESC 2024 HFpEF guidelines...", "Web search completed" x4+), поиск в PubMed ("PubMed: found 7 articles").
2. Генерация заняла ориентировочно 30–45 секунд, с несколькими последовательными обращениями к внешним источникам перед формированием финального ответа.
3. Ответ пришёл в виде развёрнутого структурированного документа: резюме случая → патофизиологическое обоснование по компонентам терапии → таблицы (препарат/уровень доказательности/данные РКИ) → визуальная ASCII-схема комбинированной терапии → таблица лекарственных взаимодействий → список противопоказаний по каждому препарату → план мониторинга и титрации → итоговое резюме схемы.
4. Ссылки на первоисточники приведены как гиперссылки с пометкой "AI analysis" (например, ссылки на FINEARTS-HF, EMPEROR-Preserved, DELIVER, FIDELIO-DKD/FIGARO-DKD).
5. После выполнения запроса счётчик кредитов в интерфейсе не изменился (остался "20" даже после обновления страницы) — либо баланс не обновляется в реальном времени, либо на тестовом аккаунте кредиты не списываются/выставлен безлимит. Это стоит проверить отдельно перед выводами о реальной стоимости использования.

## Оценка качества ответа

**Сильные стороны:**
- Клинически грамотная, актуальная и хорошо структурированная схема терапии, полностью соответствующая современным гайдлайнам по ХСНсФВ (SGLT2i как основа, финеренон как вторая линия — это действительно отражает актуальные рекомендации 2023–2025 гг., включая FINEARTS-HF, которое реально является релевантным и достаточно свежим исследованием).
- Учтена коморбидность (ХБП, СД2, стенокардия) — рекомендации по каждому компоненту сопровождаются обоснованием и данными конкретных РКИ с указанием размера эффекта (HR, ДИ, %).
- Отдельный блок по лекарственным взаимодействиям и противопоказаниям, важный для реальной клинической практики.
- План мониторинга по срокам (до старта / 2–4 недели / 3 месяца / полгода / ежегодно) — практически применим.
- Прозрачность процесса: пользователь видит, какие источники система запрашивала (это повышает доверие в отличие от "чёрного ящика").

**Слабые стороны и риски:**
- Ссылки "AI analysis" не дают прямого DOI/PMID в тексте ответа — сложно быстро проверить точность цитаты без перехода по ссылке.
- Долгое время генерации (30–45 сек) для, казалось бы, "базового" режима — неочевидно, что базовый запрос запускает полноценный веб-поиск и обращение к PubMed; это может быть неожиданно с точки зрения тарификации, если данные действия входят в стоимость "web search +1".
- Система не запросила уточнений (вес, АД, лабораторные показатели помимо СКФ/K+, сопутствующие препараты) — при реальной неполноте вводных данных это могло бы приводить к ответу, который выглядит уверенным, но опирается на предположения.
- Не выведено явного дисклеймера о том, что это не является медицинским назначением конкретному пациенту (кроме общей плашки внизу интерфейса "Always verify information...").
- Итоговый текст был явно обрезан интерфейсом при извлечении (это особенность инструмента чтения страницы, не сервиса), но в самом UI ответ прокручивается и, судя по скриншотам, полностью отрендерен.

## Итоговая оценка раздела: 8.5 / 10

Один из самых сильных и убедительных разделов платформы: сочетание генеративного ответа с видимым RAG-процессом (guideline search + PubMed + web) даёт ощущение верифицируемости, а качество клинического содержания на уровне хорошего профильного справочника/консультации.
